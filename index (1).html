flagship research
CortexIQ
Evaluating the Effect of Retrieval-Augmented Generation on LLM Answer Accuracy
Research proposal — experimental phase not yet run

CortexIQ is not a chatbot demo. It's a controlled experimental study of whether — and under what conditions — retrieval-augmented generation actually improves a language model's answers, and whether it can tell the difference between a question it can answer and one it can't.

Problem

General-purpose LLMs can produce inaccurate or unsupported answers when a question depends on organization-specific knowledge — policies, reports, procedures, KPI definitions, product details — that was never part of their training data. Retrieval-augmented generation is proposed as a fix, but whether it reliably improves accuracy and reduces hallucination for this kind of question hasn't been established through controlled testing — that's what CortexIQ sets out to measure.

Research questions
RQ1

“How does knowledge-based completeness affect an RAG system's ability to distinguish between answerable and unanswerable business questions?”

RQ2

“To what extent does Retrieval-Augmented Generation (RAG) improve the accuracy and reduce hallucinations of Large Language Model (LLM) responses when answering questions based on a defined organizational knowledge base?”

Objectives
  • Develop a RAG-based system that answers questions from a defined organizational knowledge base.
  • Implement a baseline LLM system that answers the same questions with no retrieval.
  • Evaluate CortexIQ's ability to distinguish answerable from unanswerable questions as knowledge-base completeness changes.
  • Compare response accuracy and hallucination/error rate between the RAG and baseline systems.
  • Assess the relevance of retrieved knowledge chunks and compare response time across both approaches.
Experimental design — knowledge-base completeness

The same 60-question evaluation set (40 answerable, 20 genuinely unanswerable at full completeness) is run against three controlled versions of the same knowledge base, so completeness is the only variable that changes.

A sample of the knowledge base, questions, and reference answers will be independently reviewed by someone not involved in building them, to reduce confirmation bias before the evaluation set is finalized.

System flow — baseline vs. CortexIQ

When required evidence is absent from the retrieved chunks, CortexIQ is designed to abstain — returning "insufficient information in the knowledge base" rather than generating an unsupported answer.

Evaluation framework
accuracy

Correctness of the response against a predefined reference answer.

hallucination / error rate

Unsupported claims, contradictions, or a specific answer given where the system should have abstained.

correct abstention

Whether the system recognizes insufficient information and declines rather than guessing.

retrieval relevance

Whether retrieved chunks actually support answering the question.

response time

Elapsed time from question submission to final response, baseline vs. RAG.

statistical comparison

McNemar's test, applied as a paired comparison since both systems answer the same question set.
